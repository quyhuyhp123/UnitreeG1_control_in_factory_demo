# Lightweight runtime UI / lag investigation — 2026-11-16

Default launcher now enables one RGB-D sensor image window (640×360 data, 480×270 preview, 5 Hz readback/display). Main world viewport remains available to observe/navigate the simulation. Three application panels remain: G1 Camera, G1 Keyboard Control, advanced G1 PATROL NAVIGATION. Legacy Head Camera render product is not created. Standalone YOLO debug image window is not created; YOLO boxes are rendered over its matching inference RGB in the shared camera window. Backend manager and standard Stage/Property/Content/Console/Layer panels are hidden at startup.

Start normally: `D:\unitree_g1\run_sim.bat -Factory v2`. Camera button YOLO on/off lazily starts the isolated CPU worker, then toggles submission. `-Yolo` starts it immediately. No Patrol starts automatically. Save RGB + depth + metadata still saves raw rgb.png suitable for Labelme under the runtime rgbd log folder; displayed boxes are not burned into the raw training image. A displayed YOLO frame can lag the current sensor frame, and its frame counter is shown. Sensor Enable/Disable remains available.

Major overhead found: depth geometry clustering, projected ray costmap construction, per-frame stage/self bounds traversal, multiple image providers uploading large Python lists, duplicate sensor preview render product. Prior costmap experiment recorded ~79–195 ms/update and ~3–5.5 loop FPS. Default `configs/rgbd_camera.json` now has processing_enabled=false: localization, costmap updates, static bounds precomputation, per-frame robot self bounds and continuous obstacle file writes are skipped. YOLO receives RGB without depth-fusion work in this mode. This is a deliberate pause of stage4/5 observation processing, not just hiding their windows. No navigation avoidance is removed; those experimental outputs were never driving Navigation.

Depth data capture remains available for saving but is not processed for localization/costmap by default. To explicitly restore diagnostic processing later, set processing_enabled=true before restarting (costmap debug may open and performance will decrease). Don't use lightweight-mode metadata with empty self-mask bounds as evidence of validated localization. Existing stage4/5 tests require opting back into processing to evaluate those stages.
